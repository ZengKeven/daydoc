# DayDoc 报告统计与侧边栏滚动条修复设计

## 目标

修复首页累计项目数、首页每日项目数、报告归档每日项目数，并改善报告浏览页左侧日期列表的滚动条观感。修复后统计必须直接反映历史去重索引，不能依赖 Markdown 文案格式。

## 已确认根因

`docs/reports.data.ts` 当前只匹配 `今日新增：N 个项目`，而近期报告采用 `新增项目：N 个`。未匹配时回退为 0，导致首页和归档页每日数量错误；首页累计数量又对这些错误的日报数量求和，因此停留在 24。侧边栏使用浏览器默认滚动条，没有与 DayDoc 主题统一。

## 数据设计

`docs/reports/history.json` 是去重后的仓库历史索引，作为统计唯一事实来源：

- 累计收录数：`repositories.length`。
- 每日新增数：按 `first_seen_date` 分组计数。
- 报告日期、URL 和摘要：继续从 `reports/*.md` 读取。
- 没有历史记录的报告日期显示 0；索引中存在但报告不存在的日期不生成报告卡片。
- DataLoader 同时监听 Markdown 报告和 `history.json`，任一变化都会重新生成统计数据。

DataLoader 输出从报告数组调整为包含 `reports` 与 `totalProjects` 的对象。`ReportDashboard.vue` 只消费这个对象，不再自行把日报数量相加。

## 滚动条设计

仅调整 VitePress 左侧报告导航容器：

- 轨道透明，不形成当前醒目的深色粗条。
- 滑块宽约 6px、圆角、默认低对比度。
- 悬停侧边栏或滑块时提高品牌绿色透明度。
- 同时提供 WebKit 伪元素与 Firefox `scrollbar-width` / `scrollbar-color`。
- 不隐藏滚动能力，不改变键盘、鼠标滚轮和触控行为。

## 错误处理

历史索引缺失或 JSON 无法解析时，构建应明确失败，避免悄悄发布错误的 0。单条记录缺少合法 `first_seen_date` 时不计入每日分组，但仍计入累计仓库总数，以保持累计值与历史索引一致。

## 测试与验收

1. 先添加 Node 回归测试并确认在现有实现上失败：fixture 中 388 条历史记录、2026-09-07 有 8 条，断言累计 388、当日 8。
2. 实施最小数据加载修改，使回归测试通过。
3. 执行完整测试和 `pnpm run docs:build`。
4. 检查生成 HTML：首页与归档页显示累计 388，2026-09-07 显示新增 8。
5. 用 Playwright 验证首页、归档页和报告页；检查页面身份、有效内容、控制台、日期链接交互及桌面/移动视口。
6. 对左侧滚动区域截图，确认滚动条变细、轨道透明且日期仍可滚动。

## 范围边界

不修改趋势报告内容、历史索引数据、定时任务、GitHub Actions 或其他 VitePress 视觉组件；不引入新运行时依赖。
