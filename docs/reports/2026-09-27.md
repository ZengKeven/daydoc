- **主语言/技术栈：** TypeScript、Node.js 构建工具、LLVM 后端、C/原生目标、WASI；可选 quickjs-ng。
- **主题标签：** TypeScript、JavaScript、编译器、Windows、WebAssembly。

- **当前 Star：** 5,151。

**简要介绍：** 将 TypeScript/JavaScript 编译成原生程序或 WASI 模块的实验性工具链。

**详细介绍：** 项目先把受支持的 TS/JS 代码降到类型化中间表示，再通过 C/LLVM 路线生成机器码、对象文件或可执行文件。静态路径把小型原生运行时打进产物，不依赖 Node 或 JS 引擎；遇到不能静态编译的 npm 包或动态类型代码时，可显式使用 `--dynamic` 嵌入 quickjs-ng，但会改变运行时和产物特征。

**核心能力：** 原生编译、LLVM IR/汇编/对象文件输出、部分 Node API 支持、WASI Preview 1 交叉构建、显式动态兼容模式。

**适用场景：** TS CLI/服务工具的原生部署实验、Windows/macOS/Linux 多目标构建、WASM/WASI 与 FFI 研究。

**为什么近期快速上升：** 日榜 +76，且刚发布 v0.1.6、当天仍有代码提交；编译 TS 到原生目标具有鲜明话题性。版本活动与增长同期出现，但无法证明唯一驱动因素。

**活跃度与成熟度：** 近期持续提交并发布 0.1.x；README 明示 experimental，当前有约 61 个开放 issue。跨平台目标已声明，但兼容性与 Node API 覆盖度尚不能按成熟编译器推断。

**潜在风险或注意事项：** 不能静态编译的代码会报诊断，`--dynamic` 会嵌入 JS 引擎；WASI/交叉构建需要 Zig，重建原生 helper 还需要 CMake、Ninja 与指定 LLVM。生产使用须验证依赖兼容、性能、目标平台和构建可复现性。
